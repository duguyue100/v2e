# v2e 2.0 Refactoring Plan

## Overview

This document outlines the comprehensive plan for modernizing the v2e codebase from a research-grade Python project into a well-structured, typed, tested Python library with a thin CLI wrapper.

**v2e** is a tool for generating synthetic DVS (Dynamic Vision Sensor) event streams from conventional video, using PyTorch-based Super-SloMo neural network frame interpolation and detailed DVS pixel simulation.

---

## Current State Assessment

| Aspect             | Status                                                                                       |
| ------------------ | -------------------------------------------------------------------------------------------- |
| **Packaging**      | Legacy `setup.py` only; bloated `requirements.txt` (pip freeze dump); no `pyproject.toml`    |
| **Type annotations** | ~5% of functions annotated; no mypy/pyright configured                                     |
| **Testing**        | Essentially zero — one script with no assertions, no pytest                                  |
| **Linting/Formatting** | None — no pre-commit, no ruff/black/flake8                                              |
| **Python version** | Declares `>=3.7` but README says 3.10; inconsistent across files                            |
| **Code style**     | Mixed camelCase/snake_case; mixed f-strings/`.format()`; bare excepts; wildcard imports      |
| **Architecture**   | `v2e.py` main is a 910-line monolith; empty `__init__.py` files; no defined public API       |
| **CI/CD**          | None                                                                                         |
| **Docstrings**     | Fair coverage but 3 inconsistent formats (NumPy, Sphinx, custom)                             |

### Codebase Metrics

- **~10,500 lines** across **43 Python files**
- Core library: `v2ecore/` (20 modules in 4 subpackages)
- Entry point: `v2e.py` (910-line monolithic `main()`)
- Largest module: `emulator.py` (1,196 lines)

## Decisions

| Decision                          | Choice                                              |
| --------------------------------- | --------------------------------------------------- |
| Target audience                   | Library-first (CLI is thin wrapper)                 |
| Breaking changes                  | Full rewrite / v2.0                                 |
| Python minimum                    | 3.11+                                               |
| Type checker                      | mypy (strict)                                       |
| Linter/formatter                  | Ruff                                                |
| Config system                     | Pydantic v2                                         |
| Build backend                     | Hatchling                                           |

### 1.2 — Separate I/O from `EventEmulator`

**Current problem**: `EventEmulator.__init__()` opens output files (H5, AEDAT2, AEDAT4, text). `generate_events()` writes events to these files as a side effect. This prevents library users from getting events without configuring file output.

**Solution**: Extract all output writing into `v2ecore/writer.py`:

```python
from typing import Protocol

class EventWriter(Protocol):
    """Protocol for event output writers."""

    def write(self, events: np.ndarray) -> None: ...
    def close(self) -> None: ...

class CompositeEventWriter:
    """Fans out events to multiple format writers."""

    def __init__(self, writers: list[EventWriter]) -> None: ...
    def write(self, events: np.ndarray) -> None: ...
    def close(self) -> None: ...
```

`EventEmulator.generate_events()` becomes **pure computation**: `(frame, timestamp) -> np.ndarray | None`. No file handles, no side effects beyond internal pixel state.

### 1.3 — `v2ecore/pipeline.py`: `V2EPipeline` orchestrator

New class that owns the full video-to-events pipeline:

```python
class V2EPipeline:
    """High-level API for video-to-event conversion."""

    def __init__(self, config: V2EConfig) -> None:
        self.config = config
        self.emulator = EventEmulator(config.dvs, ...)
        self.renderer = EventRenderer(config.renderer, ...)
        self.writer = self._build_writer(config.output)
        self.slomo = self._build_slomo(config.slomo) if needed else None

    def process_video(self, input_path: str | Path) -> EventStats:
        """Full pipeline: read video -> preprocess -> upsample -> events."""
        ...

    def process_synthetic(self, synth: SyntheticInput) -> EventStats:
        """Pipeline for synthetic input sources."""
        ...

    def process_frame(self, frame: np.ndarray, timestamp: float) -> np.ndarray | None:
        """Process a single frame. Low-level API for custom pipelines."""
        return self.emulator.generate_events(frame, timestamp)

    def cleanup(self) -> None:
        """Release all resources."""
        ...
```

## Phase 3: Code Quality

**Goal**: Consistent, idiomatic Python 3.11+ code.

### 3.1 — Fix naming conventions

Enforce PEP 8 across the entire codebase:

| Convention | Applies to | Examples of fixes needed |
| ---- | ---- | ---- |
| `PascalCase` | Classes | `base_synthetic_input` → `SyntheticInput`, `moving_dot` → `MovingDot` |
| `snake_case` | Functions, methods, variables | `backWarp` → `back_warp`, `numEventsWritten` → `num_events_written`, `srcNumFramesToBeProccessed` → `src_frame_count` |
| `UPPER_SNAKE_CASE` | Module-level constants | Already mostly followed |

### 3.2 — Unify string formatting

Convert all ~139 `.format()` calls to f-strings. The codebase already has ~185 f-strings, so this unifies the style.

### 3.3 — Proper error handling

**Define a v2e exception hierarchy:**

```python
class V2EError(Exception):
    """Base exception for v2e."""

class V2EConfigError(V2EError):
    """Invalid configuration."""

class V2EInputError(V2EError):
    """Invalid or missing input."""

class V2EDependencyError(V2EError):
    """Optional dependency not installed."""
```

**Specific fixes:**

- Replace 3 bare `except:` clauses with specific exception types:
  - `v2ecore/v2e_utils.py:84` — bare except on path expansion
  - `v2ecore/v2e_utils.py:265` — bare except on URL detection
  - `v2ecore/emulator.py:421` — bare except on array operation
- Replace all `sys.exit()` calls in library code with raised exceptions. Only `v2e.py` (CLI) should call `sys.exit()`.

### 3.4 — Eliminate wildcard imports

Replace all `from v2ecore.v2e_utils import *` with explicit imports. Affected files:

| Current format | Example | Action |

### 3.6 — Make numba optional

**Current state**: numba is a hard, unconditional dependency used in 5 files (7 JIT functions).

**Approach**: Wrap imports in `try/except ImportError`, provide pure-numpy fallbacks.

| Function | File | Fallback strategy |
| ---- | ---- | ---- |
| `hist2d_numba_seq` | `v2e_utils.py` | Replace with `np.add.at` loop or `np.histogram2d` |
| `search_duration_idx` | `renderer.py` | Already just two `np.searchsorted` calls — trivial |
| `normalize_frame` | `renderer.py` | Single numpy expression — trivial |
| `compute_area_counts` | `renderer.py` | Keep both paths: numba (fast, early-exit) and numpy (functional but slower) |
| `fill_dot` (×3) | `moving_dot.py`, `particles.py`, `single_linearly_moving_dot.py` | Meshgrid-based vectorized numpy |

```python
try:
    from numba import njit
    HAS_NUMBA = True
except ImportError:
    HAS_NUMBA = False
    # Define no-op decorator
    def njit(*args, **kwargs):
        def decorator(func):
            return func
        return decorator if args and callable(args[0]) is False else decorator(args[0])
```

### 3.7 — Make dv-processing optional

**Current state**: `dv_processing` is imported unconditionally at module level in `aedat4_output.py`, which is in turn imported unconditionally in `emulator.py`. This makes `dv_processing` required even when AEDAT-4.0 output is never used, and forces `numpy<2.0`.

**Fix**:

1. Lazy-import `dv_processing` inside `Aedat4EventWriter.__init__()` or `write()`.

```
Phase 0 (Foundation)       Can start immediately. Single PR.
    │
    ▼

    │                       Write tests for each module as it's refactored.
    ▼
Phase 2 (Typing)           Interleaved with Phase 1 — type each module
    │                       as it's restructured.
    ▼
Phase 3 (Code Quality)     Interleaved with Phases 1-2 — clean each module
    │                       as it's restructured.
    ▼
Phase 4 (Testing)          Partially concurrent with Phase 1 — write tests
    │                       for newly refactored modules immediately.
    ▼
Phase 5 (Docs & Polish)    Final pass after all code changes are done.
```

**Recommended module refactoring order** (within Phase 1):

1. `config.py` — no dependencies on other v2ecore modules
2. `emulator_utils.py` — pure functions, easy to test
3. `output/` writers — self-contained I/O modules
4. `emulator.py` — depends on emulator_utils and output
5. `renderer.py` — depends on emulator output format
6. `preprocessor.py` — new module, extracted from v2e.py
7. `slomo.py` + `model.py` — neural network code, mostly self-contained
8. `synthetic/` — move and rename scripts
9. `pipeline.py` — depends on all of the above
10. `v2e.py` CLI — final thin wrapper
